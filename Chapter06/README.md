## اجرای تحلیل
بسته را استخراج کنید و در ترمینال به پوشهٔ `chapter-06` بروید. دستورها داخل مفسر Python نوشته نشوند.

```bash
python -m pip install -r requirements.txt
python examples/06-walkthrough.py
python analysis.py
python answers/06-solutions.py
```

اسکریپت مثال‌ها باید از ریشهٔ فصل اجرا شود. `analysis.py` و اسکریپت پاسخ‌ها مسیر ورودی را از محل فایل می‌سازند و از پوشهٔ کاری دیگر نیز اجراشدنی‌اند. اجرای دوباره، دو فایل خروجی هم‌نام را بازنویسی می‌کند، نه فایل ورودی را.

### دفترچه
ابزارهای QA شامل هسته و اجرای غیرتعاملی دفترچه‌اند؛ خود رابط JupyterLab در این بسته نصب یا آزموده نشده است. اگر از قبل رابط Jupyter دارید، دفترچه را با هستهٔ همین محیط باز کنید. اجرای هستهٔ واقعی از طریق ابزار همراه:

```bash
python -m pip install -r requirements-qa.txt
python tests/check_notebook_kernel.py
```

در رابط تعاملی، سلول‌ها را از اول به‌ترتیب اجرا کنید. پوشهٔ کاری باید ریشهٔ فصل یا زیرپوشهٔ `notebooks` باشد. هستهٔ تازه و Run All، وابستگی‌های پنهان به اجرای قبلی را آشکار می‌کنند. نمودار با backend غیرتعاملی `Agg` ذخیره می‌شود؛ نبود پنجرهٔ نمودار خطا نیست.

## دو مسیر کدنویسی
- مسیر آموزشی: ۲۴ مثال پیوسته در متن، اسکریپت و دفترچه؛ با دستورهای مستقیم و کنترل‌های ساده.
- مسیر مرجع: `analysis.py` با توابع خواندن، محاسبه، خلاصه و نمودار؛ برای بازتولید و آزمون. لازم نیست همهٔ جزئیات سازمان‌دهی آن را در نخستین مطالعه حفظ کنید.

`load_orders` ترتیب و مجموعهٔ ستون‌ها، غیرخالی‌بودن، نبود مقدار گمشده، یکتایی شناسه، گروه مجاز و چند دامنهٔ عددی را بررسی می‌کند. نوع ستون‌های عددی هنگام خواندن تعیین می‌شود. این تابع اعتبارسنج کامل همهٔ CSVها نیست: تاریخ را تجزیه یا اعتبارسنجی نمی‌کند، خالی‌بودن معنایی متنِ فقط فاصله را به‌طور عمومی نمی‌سنجد، کامل‌بودن ثبت سفارش را اثبات نمی‌کند و کنترل سرریز اعداد بسیار بزرگ ندارد. دادهٔ معتبر کوچک و بدون این موارد، پیش‌شرط فصل است. `add_amounts` و `summarize_categories` ورودی معتبر فرض می‌کنند و ورودی را تغییر نمی‌دهند. برای مجموع مبلغ باقی‌ماندهٔ صفر، سهم‌ها `NaN` هستند، نه صفر؛ در CSV این مقدارها ممکن است به‌شکل خانهٔ خالی ذخیره شوند.

## آزمون‌ها
از ریشهٔ فصل:

```bash
python -m unittest discover -s tests -v
python tests/check_notebook_kernel.py
```

اجرای unittest و هستهٔ واقعی Jupyter دو بررسی جدا هستند. انتظارهای عددی ثابت، محاسبهٔ مستقل با کتابخانهٔ استاندارد، دادهٔ تصادفی با بذر ثابت، ورودی‌های مرزی و چند ورودی نامعتبر آزموده می‌شوند. تطبیق خروجی‌های کاتالوگ به‌تنهایی اثبات صحت مستقل نیست؛ به همین دلیل آزمون‌های عددی جدا اضافه شده‌اند.

## تمامیت فایل‌ها
`MANIFEST.sha256` برای تمام فایل‌های تحویلی جز خود manifest است. بررسی با کتابخانهٔ استاندارد، از ریشهٔ فصل:

```python
from pathlib import Path
import hashlib

root = Path.cwd()
for line in (root / "MANIFEST.sha256").read_text().splitlines():
    expected, name = line.split("  ", 1)
    actual = hashlib.sha256((root / name).read_bytes()).hexdigest()
    if actual != expected:
        raise ValueError(f"Checksum mismatch: {name}")
print("Manifest verified")
```
