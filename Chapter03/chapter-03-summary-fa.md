# فصل ۳ — پایتون ضروری: مقدار، متغیر و محاسبه

> **جلد اول · بخش اول: از مسئله تا نخستین تحلیل**  
> خلاصهٔ تخصصی برای مرور و گیت‌هاب؛ جایگزین متن آموزشی کامل نیست.

## هدف و محدوده

تبدیل داده‌های یک سفارش به محاسبه‌ای خوانا، دارای واحد و قابل‌بررسی. پیش‌نیاز: اجرای سلول و فایل پایتون مطابق فصل دوم. ساختارهای داده، شرط، حلقه و تعریف تابع به فصل‌های بعد تعلق دارند.

**خروجی:** مبلغ اولیه، مبلغ برگشتی، تعداد باقی‌مانده، مبلغ پس از کسر مرجوعی و سهم مبلغ برگشتی؛ همراه با تفسیر و محدودیت.

## ۱. قرارداد سناریو

تمام داده‌ها **ساختگی و آموزشی** هستند.

| ورودی/فرض | مقدار |
|---|---|
| شناسه | `O-0301` |
| تعداد اولیه | ۳ |
| تعداد مرجوعی | ۱ |
| قیمت واحد | ۲۴۰٬۰۰۰ تومان |
| بازپرداخت | کامل، با همان قیمت اولیه |
| تخفیف، مالیات و ارسال | در مدل نیستند |
| دامنه | یک سفارش از یک کالای هم‌قیمت |

تعدادها صحیح و نامنفی‌اند؛ مرجوعی از تعداد اولیه بیشتر نیست؛ مخرج نسبت مثبت است. کد این فصل **اعتبارسنج عمومی ورودی‌ها نیست**.

## ۲. مقدار، نوع، عبارت و انتساب

| مفهوم | تعریف کوتاه | نمونه |
|---|---|---|
| مقدار | چیزی که برنامه با آن کار می‌کند | `240_000` |
| مقدار لفظی | مقدار مستقیم در کد | `"O-0301"` |
| نوع | ماهیت مقدار و عملیات آن | `int`، `str` |
| عبارت | ترکیبی که به مقدار ارزیابی می‌شود | `3 * 240_000` |
| انتساب | اتصال نام به نتیجهٔ سمت راست | `amount = 3 * 240_000` |

- نام به شیء اشاره می‌کند؛ نوع متعلق به شیء است.
- `=` انتساب است؛ `==` مقایسهٔ مقدار است.
- تغییر ورودی، نتیجهٔ قبلی را خودکار محاسبه نمی‌کند.
- از انتساب عدد نباید نتیجه گرفت انتسابِ همهٔ اشیاء کپی مستقل می‌سازد.

```python
quantity = 3
amount_toman = quantity * 240_000
quantity = 4
print(amount_toman)  # 720000, not 960000
```

## ۳. نوع‌های اصلی

| نوع/مقدار | نمونه | نکته |
|---|---|---|
| `int` | `3`، `240_000` | برای تعداد و مبلغِ صحیح در واحد مشخص |
| `float` | `0.1` | نمایش معمولِ تقریبی اعداد اعشاری |
| `str` | `"00127"` | متن و شناسه؛ حفظ صفر آغازین |
| `bool` | `True`، `False` | نتیجهٔ مقایسه |
| `None` | از نوع `NoneType` | نبود مقدار طبق قرارداد مسئله |

`type(value)` نوع را نشان می‌دهد. `print(value)` نمایش صریح دارد و در دفترچه و فایل کار می‌کند. در فایل `.py`، عبارت تنها معمولاً خروجی نمایشی ندارد.

## ۴. نام‌گذاری و واحد

نام‌های پیشنهادی:

- `ordered_quantity`
- `returned_quantity`
- `unit_price_toman`
- `initial_amount_toman`
- `refund_amount_toman`
- `amount_after_returns_toman`
- `refund_amount_ratio`

قواعد: حروف کوچک و زیرخط؛ عدم شروع با رقم؛ حساسیت به بزرگی حروف؛ عدم استفاده از واژهٔ رزروشده یا بازنویسی نام ابزارهایی مانند `print` و `str`.

**پسوند واحد برای انسان است؛ پایتون ناسازگاری تومان و ریال را از نام‌ها تشخیص نمی‌دهد.**

## ۵. عملگرها و تقدم

| عملگر | کاربرد | مثال |
|---|---|---|
| `+ - *` | جمع، تفریق، ضرب | `3 * 240_000` |
| `/` | تقسیم معمولی | `8 / 2 == 4.0` |
| `//` | تقسیم با گردکردن به پایین | `-7 // 2 == -4` |
| `%` | باقی‌مانده | `17 % 6 == 5` |
| `**` | توان | `2 ** 3 == 8` |

نکات حساس:

- `int(-3.5) == -3`؛ تبدیل `int` با تقسیم `//` یکسان نیست.
- `-2 ** 2 == -4` ولی `(-2) ** 2 == 4`.
- `2 ** 3 ** 2 == 512`؛ توان راست‌گراست.
- برای فرمول تحلیلی، پرانتز و نام میانی را بر فشردگی ترجیح دهید.
- «بستهٔ کامل» و «بستهٔ لازم برای همهٔ کالاها» پرسش‌های متفاوت‌اند.

## ۶. رشته و تبدیل نوع

```python
print(12 + 3)       # 15
print("12" + "3")   # 123
print("12" * 3)     # 121212
```

| تبدیل | نتیجه |
|---|---|
| `int("3")` | `3` |
| `float("3.5")` | `3.5` |
| `int(3.9)` | `3`؛ حذف کسری به سمت صفر |
| `int("3.0")` | `ValueError` |
| `int("240,000")` | `ValueError` |
| `bool("False")` | `True`؛ رشته غیرخالی است |
| `bool("")` | `False` |

- `input` متن برمی‌گرداند؛ باید با قاعدهٔ مناسب تبدیل شود.
- `strip` فاصلهٔ دو انتهای متن را برمی‌دارد، نه هر آشفتگی متن را.
- `int(float(text))` می‌تواند کسری‌بودن تعداد را پنهان کند.
- تبدیل شناسه به عدد ممکن است صفرهای آغازین را از بین ببرد.
- برای ورودی ناشناس از `eval` استفاده نکنید.

## ۷. مقایسه، منطق و نبود مقدار

- مقایسه: `==`، `!=`، `<`، `<=`، `>`، `>=`.
- `3 == "3"` نادرست و `3 == 3.0` درست است؛ برابری مقدار با همسانی نوع یکی نیست.
- در ترکیب شرط‌ها از `and`، `or` و `not` استفاده می‌شود. در حالت عمومی، `and` و `or` الزاماً `bool` برنمی‌گردانند؛ در مثال‌های فصل ورودی‌شان بولی است.
- برای نبود مقدار: `value is None` یا `value is not None`.
- `None` با صفر، رشتهٔ خالی و `False` یکسان نیست.
- مبلغ نامعلوم را بدون تصمیم مستند، صفر نگذارید.
- برای مقایسهٔ معمول عدد و متن، `==` به کار می‌رود، نه `is`.

## ۸. فرمول‌های سناریو

\[
A_0 = q_0 p,\qquad R = q_r p,\qquad q_n = q_0 - q_r
\]

\[
A_n = A_0 - R,\qquad r = \frac{R}{A_0}\quad (A_0 > 0)
\]

| نماد | معنی |
|---|---|
| `q_0` | تعداد اولیه |
| `q_r` | تعداد مرجوعی |
| `p` | قیمت واحد |
| `A_0` | مبلغ اولیه |
| `R` | مبلغ برگشتی |
| `A_n` | مبلغ پس از کسر مرجوعی |
| `r` | سهم مبلغ برگشتی از مبلغ اولیه |

نتیجه: `720000`، `240000`، `2`، `480000` و حدود `0.3333`، معادل `33.33%`.

**این مبلغ سود نیست. این نسبت نیز نرخ سفارش‌های دارای مرجوعی در فروشگاه نیست.** تغییر مخرج، شاخص را تغییر می‌دهد؛ یکسانی شکل تقسیم، یکسانی معنا را تضمین نمی‌کند.

## ۹. نمایش با f-string

```python
amount_toman = 480_000
refund_ratio = 1 / 3
print(f"{amount_toman:,} تومان")   # 480,000 تومان
print(f"{refund_ratio:.4f}")       # 0.3333
print(f"{refund_ratio:.2%}")       # 33.33%
```

- `:,` جداکنندهٔ هزارگان برای نمایش می‌سازد.
- `.4f` چهار رقم اعشار نمایش می‌دهد.
- `.2%` خودش مقدار نسبت را برای نمایش در ۱۰۰ ضرب می‌کند.
- خروجی قالب‌بندی، رشته است؛ برای محاسبه از مقدار عددی اصلی استفاده کنید.
- قالب‌بندی، مقدار اصلی را تغییر نمی‌دهد.

## ۱۰. دقت و گردکردن

- `0.1 + 0.2` در محیط آزمون برابر `0.30000000000000004` است.
- `float` برای بسیاری از کاربردهای تحلیلی مناسب است؛ انتظار دقت ده‌دهیِ نامحدود از آن درست نیست.
- `math.isclose` برای مقایسهٔ تقریبی است؛ تلورانس باید با واحد، مقیاس و دقت مسئله تعیین شود. نزدیک صفر، تلورانس مطلق اهمیت دارد.
- `round(2.5) == 2` و `round(3.5) == 4`؛ در حالت دقیقاً میانی، گزینهٔ زوج انتخاب می‌شود.
- `round(2.675, 2) == 2.67` یادآور اثر نمایش دودویی است.
- برای مبلغ صحیح، `int` از خطای نمایش دودوییِ `float` دور می‌ماند؛ برای مالیات و تسهیم باید واحد و سیاست گردکردن جداگانه تعریف شود.
- `Decimal` را ترجیحاً از رشته بسازید. این ابزار نیز دقت زمینه و سیاست گردکردن دارد؛ تضمین دقت بی‌نهایت نیست.

## ۱۱. خطاها

| خانواده | نمونه |
|---|---|
| نحوی | `SyntaxError` ناشی از پرانتز بسته‌نشده |
| هنگام اجرا | `NameError`، `TypeError`، `ValueError`، `ZeroDivisionError` |
| منطقی | پرانتز جاافتاده، مخرج نادرست، واحد ناسازگار، نامیدن مبلغ به‌عنوان سود |

مسیر بررسی: انتظار دستی ← خواندن انتهای traceback ← بررسی مقدار و نوع ← اصلاح ← اجرای تازه ← بررسی معنا و واحد.

**اجرای بدون خطا، درستی تحلیل را ثابت نمی‌کند.**
