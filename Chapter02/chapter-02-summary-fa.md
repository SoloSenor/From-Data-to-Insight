## هدف فصل

ساختن محیطی که مفسر، بسته‌ها، هستهٔ دفترچه و مسیر اجرای آن شناخته شده باشند. خروجی اصلی، **یک پروژه با محیط مجازی و دفترچه‌ای قابل‌اجرا از هستهٔ تازه** است؛ صرفاً بازشدن برنامه یا نمایش خروجی ذخیره‌شده کافی نیست.

## ۱. اجزایی که نباید با هم اشتباه شوند

| جزء | نقش |
|---|---|
| Python | زبان بیان دستورها |
| مفسر | اجرای کد پایتون |
| `pip` | نصب بسته برای یک مفسر |
| `venv` | جداسازی بسته‌های پروژه |
| ترمینال و پوسته | اجرای دستورهای سیستم و راه‌اندازی برنامه‌ها |
| JupyterLab | رابط کار با دفترچه، فایل و ترمینال |
| Kernel | فرایند اجرای کد یک دفترچه |
| ویرایشگر | نوشتن و سازمان‌دهی فایل‌های کد |

مرورگر رابط کار است، نه لزوماً محل محاسبه. در نصب محلیِ این فصل، سرویس و هسته روی رایانهٔ کاربر اجرا می‌شوند.

**دستور ترمینال** مانند `python -m pip --version` را در سلول Python ننویسید. `print(2 + 3)` و `import sys` کد پایتون‌اند. در مثال‌های فصل، علامت‌های راهنمای پوسته مانند `$` و `PS>` جزو دستور نیستند.

## ۲. قرارداد نسخه و حدود آزمون

- هدف نصب جدید: **CPython معمولیِ ۶۴بیتی از شاخهٔ 3.14**؛ نه نسخهٔ آزمایشی یا ساخت free-threaded.
- مثال‌های فصل وابسته به قابلیت اختصاصی 3.14 نیستند.
- نحو و اجرای ترتیبی سلول‌های کد روی **Python 3.11.16 / Linux** بررسی شده‌اند؛ اجرای تعاملی از طریق هستهٔ واقعی Jupyter تکمیل نشد. ادعای آزمون روی 3.14، Windows یا macOS نداریم.
- دستورهای سیستم‌عامل با مستندات رسمی تطبیق داده شده‌اند؛ جزئیات آزمون در `TEST-REPORT.txt` است.
- `requirements.in` فقط نیازهای مستقیم را دارد و **فایل قفل یا محیط نهایی کل کتاب نیست**. نسخه‌های نصب موفق باید جداگانه ثبت شوند.

## ۳. نصب و شناسایی مفسر

دریافت از [صفحهٔ رسمی Python](https://www.python.org/downloads/) یا مسیر تأییدشدهٔ سازمان انجام شود. مفسر سیستم‌عامل را حذف یا جایگزین نکنید.

### Windows — مسیر مدیر نصب رسمی

پس از نصب Python install manager، در PowerShell تازه:

```powershell
pymanager install 3.14
py -V:3.14 --version
py -V:3.14 -c "import sys; print(sys.executable)"
```

اگر از قبل launcher قدیمی و runtime معتبر دارید، ابتدا `py -3.14 --version` را بررسی کنید. فرمان‌های مدیر جدید و launcher قدیمی را بدون شناخت با هم مخلوط نکنید.

### macOS

پس از نصب مناسب از منبع رسمی:

```bash
python3.14 --version
python3.14 -c "import sys; print(sys.executable)"
```

### Linux

```bash
python3 --version
python3 -c "import sys; print(sys.executable)"
```

نسخه و بستهٔ `venv` به توزیع وابسته‌اند. نصب `python3` از مخزن توزیع الزاماً شاخهٔ 3.14 را نصب نمی‌کند. از `sudo pip` یا دورزدن محدودیت محیط مدیریت‌شده استفاده نکنید.

## ۴. پوشهٔ پروژه و محیط مجازی

فایل‌های کاری را بیرون `.venv` نگه دارید. محیط باید بدون ازدست‌رفتن کد و دفترچه قابل‌بازسازی باشد.

```text
data-book/
├── .venv/
├── notebooks/
├── requirements.in
└── environment-notes.txt
```

ساخت محیط، از ریشهٔ پروژه و فقط با مسیر متناسب سیستم:

```powershell
# Windows — مدیر جدید و شاخهٔ هدف
py -V:3.14 -m venv .venv
```

```bash
# macOS — شاخهٔ هدف نصب‌شده
python3.14 -m venv .venv

# Linux — مفسر بررسی‌شدهٔ توزیع
python3 -m venv .venv
```

فعال‌سازی:

| محیط | دستور |
|---|---|
| Windows PowerShell | `.\.venv\Scripts\Activate.ps1` |
| Windows Command Prompt | `.venv\Scripts\activate.bat` |
| bash / zsh | `source .venv/bin/activate` |

کنترل پس از فعال‌سازی:

```bash
python -c "import sys; print(sys.executable); print(sys.prefix != sys.base_prefix)"
```

مسیر باید متعلق به `.venv` و مقدار بررسی محیط `True` باشد. نام محیط در ابتدای خط فرمان به‌تنهایی کافی نیست.

اگر اجرای اسکریپت فعال‌سازی در PowerShell مسدود است، بدون تغییر سیاست امنیتی از مفسر صریح استفاده کنید:

```powershell
.\.venv\Scripts\python.exe -m pip --version
```

فعال‌سازی فقط استفاده از فرمان‌های محیط را آسان می‌کند؛ هستهٔ دفترچهٔ ازقبل‌باز را تغییر نمی‌دهد. خروج از محیط با `deactivate` است. `.venv` را به دستگاه دیگر کپی نکنید؛ بازسازی کنید.

## ۵. نصب بسته و راه‌اندازی دفترچه

در محیط پروژه:

```bash
python -m pip --version
python -m pip install -r requirements.in
python -m pip check
python -c "import jupyterlab, ipykernel; print('Imports OK')"
```

محتوای نیازهای مستقیم:

```text
jupyterlab
ipykernel
```

`python -m pip` نصب را به مفسر انتخاب‌شده متصل می‌کند. `pip check` فقط سازگاری اعلام‌شدهٔ وابستگی‌ها را بررسی می‌کند، نه همهٔ رفتارها یا امنیت بسته‌ها را.

ثبت نام مشخص برای هسته و اجرای رابط:

```bash
python -m ipykernel install --user --name data-book --display-name "Python (data-book)"
python -m jupyterlab
```

`--user` در فرمان ثبت هسته، محل مشخصات kernel را تعیین می‌کند؛ به معنی نصب بسته با `pip --user` نیست. در محیط سازمانی، محدودیت ثبت هسته را رعایت کنید.

در دفترچه، هستهٔ پروژه را انتخاب و سپس بررسی کنید:

```python
import sys
from pathlib import Path

print(sys.executable)
print(sys.version)
print(sys.prefix != sys.base_prefix)
print(Path.cwd())
```

**نام هسته کافی نیست؛ مسیر اجرایی معیار مهم‌تری است.** پوشهٔ جاری نیز مبنای مسیرهای نسبی است و ممکن است با پوشه‌ای که انتظار دارید متفاوت باشد.

## ۶. وضعیت پنهان و اجرای قابل‌اعتماد

هسته متغیرها را در حافظه نگه می‌دارد. ویرایش سلول، مقدار حافظه را تغییر نمی‌دهد؛ باید سلول دوباره اجرا شود. همچنین خروجی ذخیره‌شدهٔ `.ipynb` می‌تواند متعلق به اجرای قبلی باشد.

قاعدهٔ تحویل:

1. ذخیرهٔ دفترچه؛
2. Restart هسته؛
3. اجرای همهٔ سلول‌ها از بالا به پایین؛
4. بررسی خطا، مسیر و خروجی؛
5. ذخیرهٔ دوباره.

پاک‌کردن خروجی، Restart هسته و حذف فایل سه کار متفاوت‌اند. بستن زبانهٔ مرورگر هم الزاماً سرویس یا هسته را متوقف نمی‌کند.

## ۷. ثبت نسخه و بازسازی

```bash
python --version
python -m pip freeze > requirements-snapshot.txt
```

در کنار snapshot، سیستم‌عامل، معماری، روش نصب و نتیجهٔ آزمون را ثبت کنید. فایل snapshot را از نظر محتوای حساس و کدگذاری مناسب، ترجیحاً UTF-8، بررسی کنید.

بازسازی در محیط تازه:

```bash
python -m pip install -r requirements-snapshot.txt
python -m pip check
python smoke_check.py
```

سپس دفترچه را از هستهٔ تازه اجرا کنید. `pip freeze` نسخهٔ Python، داده و اجزای سیستم را ثبت نمی‌کند و به‌تنهایی بازتولید کامل روی پلتفرم دیگر را تضمین نمی‌کند.

## ۸. خطا و امنیت

- `ModuleNotFoundError`: ابتدا مفسر هسته را با مفسر نصب مقایسه کنید.
- خطای مسیر: ابتدا `Path.cwd()` و محل واقعی فایل را بررسی کنید.
- `externally-managed-environment`: از محیط مستقل استفاده کنید.
- خطای گواهی یا proxy: تنظیم معتبر را بررسی کنید؛ بررسی گواهی را خاموش نکنید.
- token نشست Jupyter، رمز و دادهٔ شخصی را منتشر نکنید.
- **venv محفظهٔ امنیتی نیست**؛ Notebook ناشناس می‌تواند به فایل و شبکه دسترسی داشته باشد.
- `.gitignore` اطلاعات قبلاً منتشرشده یا خروجی حساس دفترچه را خودکار پاک نمی‌کند.
